# contract-diff

거래처가 고쳐 보낸 계약서(docx·md)를 원래 버전과 **조항 단위로** 비교하고, Claude Code가 의미 있는 변경만 쉬운 말과 위험도로 요약한다.
요약 항목마다 바뀌기 전·후 원문을 그대로 인용해야 하고, 그 인용이 진짜 원문의 바뀐 부분인지는 코드가 확인한다.

```
v1·v2 (docx/md) ──▶ python diff.py ──▶ out/<이름>/diff.json  (바뀐 곳 H1…Hn, 번호만 바뀐 조항)
                                              │
                    Claude Code (contract-diff 스킬) ◀┘ → out/<이름>/summary.json  (항목·위험도·전/후 인용)
                                              │
                    python check.py ◀─────────┘  (diff 는 원본 두 파일로 다시 계산)
                    ├ 인용이 그 hunk 의 원문에 있고, 바뀐 글자를 포함하는가          → 아니면 오류
                    ├ 숫자가 바뀐 hunk 를 "표현만 바뀜"에 넣지 않았나, 인용에 그 숫자가 있나 → 아니면 오류
                    ├ 요약 문장의 숫자가 인용에 있나                                → 아니면 오류
                    └ out/<이름>/변경점.md — 어디에도 안 들어간 hunk 는 맨 위 "미검토"로
```

## 쓰는 법

```bash
pip install python-docx
claude    # 이 폴더에서 열면 .claude/skills/contract-diff 가 잡힌다
> samples 의 용역계약 v1 이랑 v2 뭐가 바뀌었는지 정리해줘. 우리는 예시랩이야
```

비대화형:

```bash
claude -p "samples/용역계약_v1.docx 와 samples/용역계약_v2.docx 에서 바뀐 점 정리해줘. 우리 회사는 예시랩. 이름은 용역계약" \
  --allowedTools "Read,Glob,Grep,Skill,Bash(python:*),Edit(out/**)" --strict-mcp-config
```

**끝나면 `verify.py` 로 확인한다.** 작업 폴더는 세션이 고칠 수 있어서 믿지 않는다.
믿는 커밋(40자리 전체 해시)을 임시 폴더에 새로 꺼내(객체는 `--no-local` 로 받고 `git fsck` 로 확인) `summary.json` 하나만 가져가 그쪽 검사기·그쪽 예시 계약서로 다시 검사하고,
작업 폴더에서 `out/` 밖이 바뀌었으면 실패 처리한다. 입력·결과 경로에 링크·정션이 끼어 있으면 멈춘다.

```bash
python verify.py <믿는 커밋 40자리 해시> samples/용역계약_v1.docx samples/용역계약_v2.docx out/용역계약
```

## 검사기가 하는 일과 못 하는 일

- **잡는다:** 원문에 없는 인용(지어낸 변경), 안 바뀐 문장을 인용한 것, 14일→21일처럼 숫자가 바뀐 곳을 "표현 정리"로 넘긴 것, 요약 문장에 원문에 없는 숫자(계산한 "2배" 등), 요약에서 빠진 변경(미검토로 올림).
- **못 잡는다:** 숫자 없이 뜻이 바뀐 곳("동의를 받아" → "동의 없이")을 "표현만 바뀜"으로 넣는 것. 보고서의 표현만 바뀜 칸은 원문 전·후를 그대로 보여 주니 사람이 읽어야 한다. 위험도가 맞는지도 검사하지 않는다.
- 숫자 검사가 보장하는 건 **아라비아 숫자(0~9)뿐**이다. 요약에 "육십일", "두 배", "六十" 같은 글자 숫자를 쓰면 흔한 꼴은 거부하지만 모든 꼴을 잡지는 못한다(최선 노력). 조항 머리는 `제N조(제목)` 꼴만 알아본다.
- 보고서(변경점.md)에 들어가는 요약·이유·원문은 마크다운·HTML 기호를 이스케이프해서 넣는다. 무엇을 써도 제목·링크·접기 같은 구조가 되지 않는다.

`python test_check.py` 로 검사기 자체를 확인한다.

## 폴더

| 경로 | 내용 |
|---|---|
| `.claude/skills/contract-diff/SKILL.md` | Claude가 따르는 분류·인용 규칙과 JSON 스키마 |
| `diff.py` | 조항 단위 비교(번호 밀림·참조 번호·띄어쓰기 무시) |
| `check.py` | 인용·숫자·누락 검사 + 변경점.md |
| `verify.py` | 세션이 끝난 뒤 믿는 커밋을 새로 꺼내 그쪽 검사기로 재검사 |
| `samples/` | 예시 계약서 3쌍 — **가상 회사 '예시랩'과 지어낸 거래처의 지어낸 계약** |
| `out/` | 위 계약서로 새 세션이 실제로 만든 결과(diff.json·summary.json). 변경점.md 는 그 summary.json 을 최종 검사기로 다시 돌려 만든 것 |

예시 계약서 생성기와 정답표(어디를 바꿨는지)는 이 저장소에 넣지 않았다. 같은 폴더에 있으면 요약하는 세션이 정답을 읽을 수 있어서다.
